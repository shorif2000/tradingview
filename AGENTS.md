Handoff document for any agent (or human) picking this repo up cold. Everything
here is a **measured fact or a decision with its reason**, not a plan. If you
change something listed under [Invariants](#invariants), you are changing a

→ `backtester/validate.py`.

## 1. What this is

A regime-switching **scalping system for XAUUSD (gold)** on 2m/3m/5m, delivered
three ways that must stay behaviourally identical:

| Surface | File | Role |
|---|---|---|
| TradingView indicator | `pine/XAU_Regime_Scalper_INDICATOR.pine` | **source of truth**, ~1393 lines |
| TradingView strategy | `pine/XAU_Regime_Scalper_STRATEGY.pine` | **generated**, 1507 lines — never hand-edit |
| MT5 expert advisor | `mql5/XAU_Regime_Scalper.mq5` | 981 lines, ASCII-only, 89 inputs |
| Python backtester | `backtester/xau_engine.py` | Pine-exact port, the only place results are measured |

### Operator context (affects design decisions)

- Trades **XAUUSD via Vantage**, swap-free account.
- Signals are read on **TradingView**; orders are placed **manually on mobile MT5**.
  There is a multi-second human delay between signal and fill. This is measured
  to cost **~85% of the edge** — see [§6](#6-hard-findings).
- Account context for sizing discussions: **£100 start**, 0.01 or 0.02 lots.
- Stated goals were "90% win rate" and "90%+ PnL". **Neither is achievable** on
  this data; do not tune toward them. See [§7](#7-things-that-do-not-work).

## 3. Invariants

Do not change these without re-measuring and updating the numbers in `README.md`,
`docs/HOW_TO_TRADE_IT.md` and this file.

| # | Invariant | Why |
|---|---|---|
| I1 | `tfK = max(5.0 / tfMin, 1.0)` — **clamped at 1.0** | Unclamped, a 1h chart got EMA 2/4/17, pivot 2, ATR x0.29 and an impulse threshold of $5.75 instead of $19.86, producing 286 spurious order blocks (119 after the fix) |
| I2 | Strategy SL/TP reset guarded by `if strategy.position_size == 0 and not goLong and not goShort` | `strategy.position_size` is 0 on the entry bar, so the naive guard wiped SL/TP the same bar it set them |
| I3 | Python EMA uses `_seeded_ewm` with an SMA seed | `pandas.ewm` differs from Pine `ta.ema` for the first `len` bars; unseeded, the port diverges |
| I4 | Percentages computed as `100.0 * wins / tot` | Integer division silently returned 0 |
| I5 | SMC block declared **above** the limit-entry block | `obBuyTop` / `obSellBot` were used before declaration |
| I6 | Zone/box cosmetics run under `barstate.islast`; state updates run every bar | Redrawing zones on every historical bar froze the browser tab |
| I7 | Reason labels capped at `maxReasonLbl` (default 2), oldest shifted off | Labels overlapped into unreadable congestion |
| I8 | MTF bias uses EMA **20/50** and masks NaN to 0 (unknown) | `EMA50 > EMA200` with NaN evaluates False, so "no history" was reported as "downtrend" |
| I9 | Volume-imbalance boxes skip their creation bar via `box.get_left(...) < bar_index - 1` | Otherwise the box fills on the bar that created it |
| I10 | Pine ternaries wrapped at **18 spaces max** | 36-space continuation indent is a hard Pine compile error |
| I11 | Input group constants are unique (`gRM` for Roadmap, not `gR`) | Duplicate `gR` between Regime and Roadmap = compile error. When renaming, catch **both** `group=gR` and `group = gR,` forms |
| I12 | One indicator handles all four jobs via the `scriptMode` dropdown | TradingView caps studies per chart; a 4-script split hit "maximum number of studies per chart" |
| I13 | Backtest resolves intrabar order from **M1** data, SL-first on ties | A 2R system's result depends entirely on which of SL/TP is touched first |
| I14 | Spread taken from the MT5 `<SPREAD>` column, bid-price assumption | $0.20 spread against a $3 stop is ~7% of risk per trade |
| I15 | Ruin + margin modelled explicitly | An early run drove the account to **-£121**, which is not a possible outcome |

## 4. Architecture

### Regime classification

ADX(14) + Bollinger-width percentile, with **hysteresis**: enter TREND above
ADX 23, only leave below 18. Prevents bar-to-bar flicker. States: TREND, RANGE,
stand-aside.

### Entry modules

| Module | Trigger | Status |
|---|---|---|
| **Range fade** | Price pokes outside a Bollinger band at a range extreme and closes back inside (failed breakout) | **ON** — carries the system |
| **Liquidity sweep** | Price runs stops beyond a swing level and closes straight back (failed stop raid) | **ON** — complementary to range fade |
| **Trend pullback** | Buy dips into the EMA20 zone with H1 trend agreeing | **OFF** — loses money |
| **Breakout continuation** | Continuation after a range break | **OFF** — Python only, never wired into Pine |

Range and sweep are kept **together** because together they beat either alone on
both expectancy and drawdown. Trend and breakout are **split out into variant 3**
because bolting them on drags the pair from +0.368R to +0.198R.

### Confirmation scoring

No signal fires on one condition. Candidates collect independent reasons — swept
level reclaimed, engulfing, pin bar, RSI reclaiming 50, higher low, +DI expanding,
divergence — and need at least N (default 2). Reasons are printed on the chart and
in every alert. **A tie between long and short is skipped, not resolved.**

> **Counter-intuitive but measured:** adding more confirmations *reduces*
> expectancy, because more routes to the score minimum lets weaker setups through.
> SMC votes: +0.29R -> +0.06R. Reversal votes: +0.37R -> +0.23R. Do not "improve"
> this by adding confirmations.

### Stops and targets

Stop beyond structure (8-bar swing / rejection wick / liquidity wick), padded
0.35 x ATR, floored 0.8 x ATR, capped 2.0 x ATR. **If structure is further than
the cap, the trade is skipped** rather than taken with oversized risk.

### SMC layer

BSL/SSL liquidity pools (labelled with touch count), order blocks (translucent
blue = buy, red = sell), breaker blocks (yellow), volume imbalance (light blue,
close-to-open **body** gap — distinct from a wick-to-wick FVG). FVG/IFVG were
**removed on request** — the operator has other scripts for those.

Zone rules: minimum confluence count to draw at all; `HIGH RISK` + dotted thin
border when a zone only just clears the minimum; untouched zones extend across
the chart; visited zones freeze/grey unless strong; hover shows exact high/low
and the confluence list.

### UI gating

Two orthogonal mechanisms:

```pine
scriptMode = "Scalper" | "Liquidity map" | "Roadmap" | "Everything" | "Custom"
f_mode(userFlag, onInThisMode) => modeCust ? userFlag : onInThisMode
// 18 effective display flags, e.g.
eShowOB = f_mode(showOB, modeMap or modeAll)

uiPreset = "Beginner" | "Standard" | "Full" | "Custom"
f_show(userFlag, needRank)
```

16 input groups, numbered (0)-(16), no duplicate group constants.

### Roadmap module

Calibrated logistic on which liquidity level is reached first:

```
p = 1 / (1 + exp(-(2.2929 - 4.6045 * ratio)))
```

9,994 observations, **Brier 0.197** vs 0.25 for guessing. Median resolution 9 bars
(~45 min on 5m). Volatility cone at **0.96** and **2.19** x ATR x sqrt(bars) for
68%/95% bands — constants held across both samples and horizons 6-48 bars.

The roadmap **never calls direction**. It maps destinations and spread only.

## 5. Backtest realism model

- Bid-price assumption; spread from the MT5 `<SPREAD>` column
- M1-resolved intrabar fill ordering, **pessimistic SL-first tie-break**
- Lot-step rounding at 0.01 granularity (partial scale-out needs >= 0.03 lots)
- Margin and ruin modelling
- Statistics: bootstrap CIs, Wilson intervals, Brier score, permutation tests,
  walk-forward, MFE/MAE, R-multiples

### Timezone — verify, never assume

| Source | Timestamps | Loader arg |
|---|---|---|
| MT5 export | broker server time = **UTC+2** (Jan) | `--assume-tz Etc/GMT-2` |
| TradingView export | **UTC** | `--assume-tz UTC` |

Verify from the data: gold has a one-hour daily break at 22:00-23:00 UTC in
winter, 21:00-22:00 in summer. Find the missing hour and pick the offset that
puts the gap there. `Etc/GMT-2` means UTC+2 — the sign inversion is correct.
An early run was 2h-shifted because UTC+3 was assumed.

## 6. Hard findings

Measured on 2M Jan + 5M Jan + 5M Jun-Aug, **0.02 lots, half off at 1R, swing trail**:

|---|---|---|---|---|---|
| **Range + Sweep together** | **151** | **57.0%** | **+0.368R** | **+£384** | **14%** |
| Range fade alone | 141 | 56.0% | +0.321R | +£353 | 48% |
| Liquidity sweep alone | 63 | 54.0% | +0.314R | +£92 | 24% |
| Trend pullback alone | 63 | 44.4% | -0.093R | -£68 | 75% |
| Breakout alone | 49 | 40.8% | -0.076R | -£21 | 67% |

| 0.02, half at 1R + break-even | 163 | 52.8% | +0.157R | 41% |

Per timeframe on the winning plan:

| Sample | Green | Expectancy | Net | DD |
|---|---|---|---|---|
| 2M January | 50.0% | +0.268R | +£53 | 36% |
| 5M January | 61.5% | +0.259R | +£61 | 29% |
| 5M June-August | 59.1% | +0.502R | +£270 | 14% |

### Directional predictors — replication test

Asked at every bar: is the nearest liquidity **above** taken before the nearest
**below**? Two independent samples:

| Predictor | Sample A | Sample B | Verdict |
|---|---|---|---|
| **Proximity** (which level is closer) | **86.9%** | **86.4%** | **replicates — the only real edge** |
| H1 trend up | 54.8% | 43.1% | flipped sign — spurious |
| Fresh SSL sweep | 61.6% | 38.4% | flipped sign — spurious |
| Regime = RANGE | 58.9% | 46.2% | flipped sign — spurious |

**Only proximity forecasts direction.** Trend, regime and sweep state are worthless
for it. None of them feed the roadmap script.

### Other measured facts

- **Break-even stops cost money**: +0.291R -> +0.175R. Gold routinely retraces
  through entry before continuing. Leave the stop alone until at least +1R.
- **Session filter matters**: 07:00-20:00 London. Trading 24h costs **92%** of the edge.
- **Weekly re-tuning does not pay**: refit weekly gave +0.506R out-of-sample vs
  **+0.579R for leaving defaults alone**.
- **Manual mobile execution costs ~85% of the edge** vs instant fills.
- **Selection bias is real**: with all three modules on (pre-selection) the January
  + summer samples give +0.215R over 166 trades, CI -0.004 to +0.440R — touching
  zero. The +0.291R headline is post-selection. Treat the pre-selection number as
  the trustworthy one.

## 7. Things that do not work

Do not re-attempt these without new evidence. Each was tested and failed.

1. **Trading with the trend on short-horizon gold.** Three independent attempts:
   trend pullback (-0.09R), H1 trend gating (+0.485R fell to +0.117R), breakout
   continuation (-0.08R). Consistent across regimes and timeframes. At a 20-cent
   spread there is not enough left in a continuation move to pay for the entry.
   **Short-horizon gold mean-reverts.**
2. **Adding confirmations to raise win rate.** It lowers expectancy (see §4).
3. **Break-even stops.** -0.12R per trade.
4. **Weekly parameter tuning.** Loses to doing nothing, and leaves a fitted
   parameter set that may not survive the next regime.
5. **A 90% win rate.** Not reachable. The best measured configuration is 57% green
   at +0.368R. A system can be excellent at 57%.
6. **Splitting into four separate TradingView scripts.** Hits the studies-per-chart
   cap. Use `scriptMode` instead (I12).

## 8. Known environment constraints

| Constraint | Detail |
|---|---|
| Market-data hosts | All blocked from the build sandbox (403/502). Data must be supplied as CSV exports. |
| `api.github.com` | 502 from the sandbox. |
| `GITHUB_TOKEN` / `GH_TOKEN` in sandbox | Literal placeholder string `proxy-injected` — not a credential. Never solicit or accept a real token. |
| Device bridge (`device_bash`) | **No network.** `git push` must be run by the operator. |
| Device bridge deletes | `rm` is blocked ("Operation not permitted"). `mv` into a `_to_delete/` folder instead. Git leaves `.lock` files it cannot clean up — clear `HEAD.lock`, `index.lock`, `refs/heads/*.lock` before any git write, or use `commit-tree` + `update-ref` to bypass the index. |
| TradingView history caps | ~5,000 5m bars free, 10,000 Essential/Plus, 20,000 Premium. Six months of 5m gold is ~37,000 bars — the Strategy Tester cannot cover a long sample. That is what the Python backtester is for. |
| Credentials | Operator login details and OAuth sign-in are **declined on principle**, regardless of offered permission. |

## 9. Open items

- **Settle the statistics.** Export **6+ months of M5 or M1** from MT5 (View →
  Symbols → XAUUSD → Bars tab → date range → Export Bars). At this effect size
  ~180-200 trades decides it; six months gives 300-400. Everything is wired —
  drop the file in `data/` and run `run_backtest.py`.
- **2M has one sample only** (January, 46 trades). 5M has two that agree. Do not
  present 2M results with the same confidence as 5M.
- **Sizing is the binding constraint, not signal quality.** 0.02 lots on £100 is
  £6-9 risk per trade (6-9% of the account). Recommendation: 0.01 below £250,
  0.02 at £250+. This cannot be backtested away.
- **Breakout module is Python-only** (`use_breakout_module`). It was never wired
  into Pine because it measured -0.08R.
- **Automation** would recover most of the ~85% of edge lost to manual execution.
  The MQL5 EA exists for this; it has not been run live.
